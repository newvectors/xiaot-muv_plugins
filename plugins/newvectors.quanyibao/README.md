# 权益宝（newvectors.quanyibao）

对接 [权益宝](https://www.quanyibao.com) 的资源搜索插件：登录后用积分解锁影视资源，把 115 网盘分享链接交给 Muvyo 转存。

## 能力

| 能力 | 说明 |
|---|---|
| `search` + `resolve` | 搜片名 → 找到该影片的资源帖 → 需要时用积分购买 → 返回 115 分享链接与提取码 |
| `tasks` | 「每日积分签到」，默认每天一次，执行时间在插件设置的「定时任务」里改；多账号会依次签 |
| `account` | 设置页顶部显示**登录测试结果**与每个账号的剩余积分 |

## 配置

| 项 | 说明 |
|---|---|
| 多账号（一行一个） | `账号\|密码`，一行一个；第 1 行是主账号，最多 12 个。填了这里就忽略下面的「账号」「密码」 |
| 账号 | 单个账号时用。手机号写成 `86 13800138000`（区号 + 空格 + 号码），或直接填邮箱 |
| 密码 | 只存本机，用于自动登录换令牌 |
| 每次最多查询影视数 | 关键词搜索时取前几部作品去查资源帖，默认 3 |
| 每部最多网盘条目 | 一部作品最多交出几个网盘条目，默认 2 |
| 允许扣积分购买 | 关闭后只给已解锁的资源，不会花积分 |
| 积分不足时换账号 | 当前账号买不起时自动换下一个账号付款；关掉就只在主账号上试 |
| 优先 4K/1080P | 同一作品多个资源时，分辨率高的排前面 |
| 自定义 User-Agent | 一般不用改。想和自己浏览器完全一致时，从 `chrome://version` 复制整行「用户代理」贴进来 |

## 请求头（不做显眼的自动化特征）

`mv.fetch` 不设 `User-Agent` 时默认带 `Muvyo-Addon/1`，再缺 `Accept-Language`、`sec-ch-ua`，等于把「这是插件」写在请求上。1.1.1 起每个请求都按真实浏览器的形态发出：

| 头 | 值 |
|---|---|
| `User-Agent` | 内置 Chrome 147 / macOS（与抓包一致），或设置里自定义 |
| `Accept-Language` | `zh-CN,zh;q=0.9` |
| `sec-ch-ua` / `-mobile` / `-platform` | 由 UA 反推，保证与 UA 自洽（Safari / Firefox 不发这组头，插件也不发） |
| `Referer` | 跟随当前操作：搜索是 `/search?key=…`，取链与购买是 `/article/<postId>`，登录/签到是 `/` |
| `Origin` | 仅 POST，`https://www.quanyibao.com` |
| `sec-fetch-dest/mode/site` | `empty` / `cors` / `same-origin` |

填了非 `Mozilla/5.0` 开头的值时会被忽略并退回内置 UA，避免把昵称之类当成 UA 发出去反而更刺眼。

> 注：UA 与请求头只是 L7 指纹。TLS 指纹（JA3/JA4）、HTTP/2 帧序、请求节奏仍可能与真浏览器不同——站点目前在 Cloudflare 后面，实测这些头都能正常通过，没有触发挑战。

## 登录测试与多账号

Muvyo 的配置项没有按钮类型，所以「测试登录」不是单独一个按钮，而是账号面板本身：

- 填好账号后点**保存**，插件会立刻逐个账号真登录一次、读一次积分，结果显示在设置页顶部（失败会写清原因，并进插件日志）；
- 之后随时点账号栏右上角的**刷新**可以再测一次；
- 测通后 `authToken`/`refreshToken` 与积分按账号分别存进 `mv.storage`（`qyb_accounts_v2`），下次直接复用，读到 `exp` 快过期才重新登录。

多账号的规则：

| 场景 | 行为 |
|---|---|
| 每日签到 | 按设置顺序逐个账号签，每个账号单独记「今天签过没有」；某个账号登录失败只影响它自己 |
| 买片 | 先查所有账号有没有已经解锁（有就直接取链，一分不花）→ 都没解锁再按顺序挑积分够的账号付款 → 不够自动换下一个 |
| 已解锁记录 | 站点按账号判断解锁，本地记录也带账号指纹；换了账号不会误判成「已买过」 |
| 删账号 | 从文本框删掉后，它的令牌与记录会在下次调用时一并清掉，不占存储 |

## 不会重复扣分

站点自身的购买接口没有资源级幂等：对已解锁的资源再次调用会**再扣一次积分**。

本插件在每次取链前都会重新读一次该资源帖的服务端状态（`auth.pageData` 里的 `allow`）：

- `allow = true`（已解锁）→ 直接取链，**不调用购买接口**；
- 任一账号已解锁 → 用那个账号取链，不让别的账号再买一次；
- 未解锁 → 先比余额，够了才买，且只买一次；
- 买了但没拿到链接（超时、5xx、响应异常）→ 按 `uncertain` 上报，提示到站点核对，**不会自动重试、也不会换账号再试**；
- 站点明确回 `success: false`（确定没扣分）→ 才允许换下一个账号。

另外本地还留了一份已解锁记录（`mv.storage`，按账号指纹分开），作为服务端状态读不到时的兜底。

## 出错时怎么查

所有异常都写进 Muvyo 的**插件日志**（「第三方插件 → 本插件 → 日志」），界面上的报错和日志里是同一句话，不会出现「界面上说有错、日志里查不到」。

日志按步骤打前缀，一眼能看出错在哪一步：

| 前缀 | 这一步在做什么 | 出错时日志里会写 |
|---|---|---|
| `[登录]` | 用账号密码换令牌 | 接口名 `auth.login`、HTTP 状态、`statusCode`、站点原话 |
| `[搜索]` | 查作品 → 查资源帖索引 → 读资源帖 | 失败的接口（如 `GET /api/film/catalog`）、`postId`、是否降级返回 |
| `[取链]` | 读解锁状态 → 购买 → 取下载链接 | `auth.pageData` / `mutates.pay` / `mutates.resourceDownload`、`postId`、价格、耗时 |
| `[签到]` | 定时签到 | 登录失败原因、`mutates.checkin` 的状态与错误码 |
| `[账号]` | 设置页顶部的登录测试与积分 | 哪个账号登录失败、`auth.viewer` 读不到账号的原因 |

几条原则：

- 日志里**不会**出现密码、Cookie、`authToken`/`refreshToken`、分享码，统一打码成 `***`。
- 单次调用最多写 32 条、每条 360 字以内，相同的告警只写一次，避免循环刷屏把关键信息挤掉。
- 每条日志都带「是什么错 + 错在哪个接口 + 站点怎么说的」，例如：
  `ERROR [取链] 登录失败：账号或密码不正确（403）｜postId=84，请检查插件设置里的账号与密码`
  `WARN  [取链] 购买请求已发出但没收到响应（接口 mutates.pay 网络不可用），可能已扣积分，请到权益宝核对后再试｜postId=84 index=0 价格 10`

常见报错对照：

| 界面提示 | 多半是 | 怎么办 |
|---|---|---|
| `登录失败：账号或密码不正确（403）` | 账号密码错 / 手机号格式不对 | 手机号写成 `86 13800138000` |
| `读取资源状态失败：auth.pageData 返回的不是 JSON` | 站点改版或返回错误页 | 稍后重试；持续出现请提 issue |
| `积分不足：当前 3，需要 10` | 积分不够 | 等每日签到、加一个账号，或到站点充值 |
| `已扣积分但…请到权益宝核对` | 购买可能成功但取链失败 | **不要重复点**，先到权益宝「我的积分」看记录 |
| `站点不允许下载这条资源` | 该条目受限制 | 换一条资源 |

## 接口要点（开发备忘）

- 查询走 REST GET，写操作走统一 RPC `POST /api/request {action, data}`；业务失败同样返回 HTTP 200，要看 body 里的 `statusCode` / `success` / `errorCode`。
- 按影片取资源的正确链路是 **`/api/film/catalog?ids=tv:1399`（批量，返回 `postId`）→ `auth.pageData` 读 `/article/<postId>`**。
  `/api/film/resources` 是「资源库浏览」接口，**不按影片过滤**，别拿它当单片资源列表。
- 搜索结果条目的主键字段是 `id`（tmdbId），`catalog` 里才叫 `tmdbId`；单条详情包在 `item` 下。
- 购买参数 `args` 必须是**字符串化 JSON**，`payment` 固定 `film_credit`。
- `loginData.module` 的 key 是随机串，只能遍历 `values` 按结构识别。
